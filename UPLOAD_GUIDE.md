# Upload Guide

1. Create a new repository for the paper data.
2. Upload the **contents of this folder**, not the zip itself, so reviewers can browse the CSVs directly.
3. Keep the folder hierarchy exactly as provided.
4. Put `README.md`, `DATA_DICTIONARY.md`, and `manifest.csv` at the repository root.
5. Do not rename individual CSVs after linking the repository in the submission system.
6. If code is added later, create a top-level `code/` directory and document how to run it in the README.
7. After the repository is final, create a tagged release (for example `v1.0-submission`) so the reviewed dataset has a stable snapshot.
8. Consider archiving the release in a research-data repository that issues a DOI after the anonymity requirements of peer review are satisfied.

## Anonymity warning

If the journal is using double-anonymized review, a repository hosted under a personal GitHub account can reveal the authors' identities through the account name, profile, commit history, or repository metadata. Use a submission method that preserves anonymity, or follow the journal/editorial office's instructions for anonymized research-data links. Do not add author names, affiliations, e-mail addresses, acknowledgements, or identifying metadata to the review-stage data package.
